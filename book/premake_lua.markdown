# Using Premake for OmniScript++ (OS) Project Setup

The OmniScript++ (OS) project, which includes the `Osengine` compiler for the OS programming language, uses **Premake** as its build system generator. Premake is a lightweight, open-source tool that generates build files (e.g., Makefiles, Visual Studio solutions) from a single configuration script, ensuring cross-platform compatibility and streamlined project management. This document explains how to download and use Premake, the structure of the provided `premake5.lua` script, and why Premake is essential for professional-grade projects like OS, particularly for smart rebuilds and dependency management.

## Why Premake?

Premake is chosen for the OS project because it:
- **Simplifies Build Configuration**: A single `premake5.lua` script defines the build process for all platforms (Windows, Linux, macOS) and toolsets (GCC, Clang, MSVC).
- **Supports Smart Rebuilds**: Generates Makefiles (via `gmake2`) that track dependencies and rebuild only modified files, reducing build times.
- **Handles Complex Dependencies**: Manages external libraries like LLVM, pthread, and quadmath, ensuring correct include paths and linker flags.
- **Ensures Consistency**: Produces consistent build configurations across Debug and Release modes, architectures (x64), and platforms.
- **Scales for Professional Projects**: Simplifies maintenance for large projects with multiple configurations, making it ideal for OS’s compiler development.

By using Premake, the OS project achieves a robust, maintainable, and efficient build pipeline, critical for a professional-grade compiler leveraging LLVM for JIT and AOT compilation.

## Project Structure

The OS project, named `OmniScript++`, follows this structure:
```
OmniScript++/
├── build_tools/
│   └── premake/
│       └── premake5.exe  # Premake executable
├── dependencies/
│   └── llvm/            # LLVM libraries and headers
│       ├── include/
│       ├── lib/
│       └── bin/         # LLVM DLLs (Windows)
├── src/                 # Source files for Osengine (*.cpp)
├── include/             # Header files for Osengine
├── bin/                 # Output directory for executables
├── bin-int/             # Intermediate object files
└── premake5.lua         # Premake configuration script
```

- **build_tools/premake/**: Contains `premake5.exe`, the Premake executable.
- **dependencies/**: Stores external libraries, including LLVM, with headers in `include/` and libraries in `lib/`.
- **src/**: Contains C++ source files for the `Osengine` compiler.
- **bin/** and **bin-int/**: Output directories for executables and intermediate files, respectively, organized by configuration (e.g., `Debug-windows-x64`).
- **premake5.lua**: The configuration script defining the build process.

## Downloading Premake

To set up Premake for the OS project:
1. Visit the [Premake GitHub releases page](https://github.com/premake/premake-core/releases).
2. Download the latest version of Premake (e.g., `premake-5.x.x-windows.zip` for Windows or `premake-5.x.x-linux.tar.gz` for Linux).
3. Extract the archive and place `premake5.exe` (or `premake5` for Linux/macOS) in the `build_tools/premake/` directory:
   ```
   OmniScript++/build_tools/premake/premake5.exe
   ```
4. Ensure the executable has appropriate permissions (e.g., `chmod +x premake5` on Linux/macOS).

## Using Premake with `premake5.lua`

The provided `premake5.lua` script configures the `OmniScript++` workspace and the `Osengine` project. Here’s how to use it:

### Step 1: Generate Build Files
Run Premake with the `gmake2` action to generate Makefiles:
```
cd OmniScript++
build_tools/premake/premake5.exe gmake2
```
- This generates Makefiles in the project root, tailored for `make` (GNU Make).
- The `gmake2` action ensures compatibility with modern Make features, enabling smart rebuilds.

### Step 2: Build the Project
Use `make` to build the `Osengine` compiler:
```
make
```
- By default, this builds the `Debug` configuration.
- For the `Release` configuration, run:
  ```
  make config=release
  ```
- The build process:
  - Compiles `src/*.cpp` files into object files in `bin-int/[config]-[system]-[arch]`.
  - Links against LLVM, pthread, and quadmath libraries.
  - Outputs the executable to `bin/[config]-[system]-[arch]/Osengine` (or `Osengine.exe` on Windows).
  - On Windows, copies LLVM DLLs to the output directory via `postbuildcommands`.

### Step 3: Smart Rebuilds
Makefiles generated by Premake track file dependencies, ensuring only modified files are recompiled. For example:
- If you modify a file in `src/`, running `make` recompiles only that file and relinks the executable.
- This minimizes build times, crucial for iterative development of a compiler like `Osengine`.

### Step 4: Clean Builds
To clean the build artifacts:
```
make clean
```
This removes object files (`bin-int/`) and executables (`bin/`) for the current configuration.

## Understanding `premake5.lua`

The `premake5.lua` script defines the build configuration for `OmniScript++`. Below is a breakdown of its key components:

### Workspace Configuration
```lua
workspace "OmniScript++"
    configurations { "Debug", "Release" }
    architecture "x64"
```
- Defines the workspace `OmniScript++` with `Debug` and `Release` configurations.
- Targets x64 architecture for all builds.

### Output Directories
```lua
outputdir = "%{cfg.buildcfg}-%{cfg.system}-%{cfg.architecture}"
```
- Dynamically sets output directories (e.g., `bin/Debug-windows-x64`, `bin-int/Release-linux-x64`).

### Debug Configuration
```lua
filter "configurations:Debug"
    defines { "DEBUG" }
    symbols "On"
    optimize "Off"
```
- Enables debug symbols and defines `DEBUG` for conditional compilation.
- Disables optimizations for faster compilation and easier debugging.

### Release Configuration
```lua
filter "configurations:Release"
    defines { "NDEBUG" }
    optimize "On"
```
- Defines `NDEBUG` and enables optimizations for performance.

### Sanitizers (Debug, Non-Windows, GCC/Clang)
```lua
filter { "configurations:Debug", "system:not windows", "toolset:gcc or clang" }
    buildoptions { "-fsanitize=address", "-fno-omit-frame-pointer" }
    linkoptions  { "-fsanitize=address" }
```
- Enables AddressSanitizer for memory error detection on non-Windows platforms with GCC or Clang.

### Sanitizers (Debug, Windows, Clang)
```lua
filter { "configurations:Debug", "system:windows", "toolset:clang" }
    buildoptions { "-fsanitize=address", "-fno-omit-frame-pointer" }
    linkoptions  { "-fsanitize=address" }
```
- Enables AddressSanitizer for Windows with Clang.

### Project: Osengine
```lua
project "Osengine"
    kind "ConsoleApp"
    language "C++"
    cppdialect "C++23"
    targetdir ("bin/" .. outputdir)
    objdir ("bin-int/" .. outputdir)
```
- Defines `Osengine` as a console application using C++23.
- Sets output directories for executables and object files.

### Source Files and Includes
```lua
files { "src/**.cpp" }
includedirs {
    "include",
    "dependencies/llvm/include"
}
```
- Includes all `.cpp` files in `src/`.
- Specifies include paths for project headers and LLVM.

### Library Dependencies
```lua
libdirs { "dependencies/llvm/lib" }
links {
    "LLVM-20",
    "pthread",
    "quadmath"
}
```
- Links against LLVM, pthread, and quadmath libraries from `dependencies/llvm/lib`.

### Windows-Specific Configuration
```lua
filter "system:windows"
    defines { "PLATFORM_WINDOWS" }
    systemversion "latest"
    links { "ucrt", "msvcrt" }
    postbuildcommands {
        "powershell -Command \"if (-not (Test-Path -Path 'bin/%{cfg.buildcfg}-%{cfg.system}-%{cfg.architecture}')) { New-Item -ItemType Directory -Force -Path 'bin/%{cfg.buildcfg}-%{cfg.system}-%{cfg.architecture}' }\"",
        "powershell -Command \"Copy-Item 'dependencies/llvm/bin/*.dll' -Destination 'bin/%{cfg.buildcfg}-%{cfg.system}-%{cfg.architecture}'\""
    }
```
- Defines `PLATFORM_WINDOWS` for platform-specific code.
- Links Windows libraries (`ucrt`, `msvcrt`).
- Copies LLVM DLLs to the output directory post-build.

### Stack Probe Option
```lua
filter { "system:windows", "toolset:msc*" }
    buildoptions { "/mno-stack-arg-probe" }
filter { "system:windows", "toolset:not msc*" }
    buildoptions { "-mno-stack-arg-probe" }
```
- Disables stack probes for compatibility with certain toolsets.

## Why This Setup for OS?

The `premake5.lua` configuration is tailored for a professional-grade project like OS because:
- **Cross-Platform Support**: Handles Windows, Linux, and macOS builds with platform-specific tweaks (e.g., DLL copying on Windows).
- **Dependency Management**: Seamlessly integrates LLVM, a critical dependency for OS’s JIT and AOT compilation.
- **Smart Rebuilds**: Makefiles ensure efficient incremental builds, vital for rapid iteration during compiler development.
- **Debugging and Optimization**: Supports Debug (with sanitizers) and Release (optimized) configurations.
- **Scalability**: The workspace structure allows adding more projects (e.g., tests, tools) as OS grows.

## Additional Dependencies

The `Osengine` project relies on:
- **LLVM**: Located in `dependencies/llvm/`, used for IR generation, optimization, and codegen.
- **pthread**: For threading support (e.g., in the starfield example).
- **quadmath**: For high-precision math operations.
- On Windows, `ucrt` and `msvcrt` provide standard C runtime functionality.

Ensure these dependencies are installed in `dependencies/` as specified in the project structure. For LLVM, download version 20 from the [LLVM releases page](https://releases.llvm.org/) and place it in `dependencies/llvm/`.

## Example Workflow

1. **Setup**:
   - Place `premake5.exe` in `build_tools/premake/`.
   - Ensure LLVM is in `dependencies/llvm/`.
2. **Generate Makefiles**:
   ```
   build_tools/premake/premake5.exe gmake2
   ```
3. **Build Debug**:
   ```
   make
   ```
4. **Build Release**:
   ```
   make config=release
   ```
5. **Run Osengine**:
   ```
   bin/Debug-windows-x64/Osengine.exe docs/examples/opengl/shaders/starlikeglad.os
   ```
   or, for AOT:
   ```
   bin/Release-windows-x64/Osengine.exe docs/examples/opengl/shaders/starlikeglad.os --make -o app.exe
   ```
